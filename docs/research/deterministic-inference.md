## Where today's progress came from

On the run `smb-side-by-side-2` Super Mario Bros. went from 49% of clips exact to 66% today (170 of 256 now, from `GET /api/capture/smb-side-by-side-2/background`). None of it came from fitting numbers. The run's `history.jsonl` has 426 rounds and only rounds 1 to 3 (2026-10-29) kept a number, all three wrong and since put back to the code's values. The ledger has 389 refine rounds and none kept a number (docs/research/refine-loop-study.md has the first 294). Every gain came from a lane, an LLM, that read the first wrong frame, found the routine in SMBDIS.ASM, and added a general mechanic option with the code's numbers:

The rest of this note is about which parts can be done by deterministic algorithms, and which test results say which one to run.

## 1. The pipeline and where an LLM is still needed

| Stage | Today | LLM needed today? | Deterministic method that could replace it |
|---|---|---|---|

| Timers and phases | Lanes read TimerControl, FrameCounter checks, IntervalTimerControl | Yes | Counter detection and change points (A6), modulo detection (A7) |
| Fitting | The refine loop; it kept nothing in 389 rounds | No, but it rarely helps | Exact arithmetic recovery (A8) before any search; CEGIS where a search is needed (A5) |

| Assets | `gp assets lift` with a hand-written asset map per ROM | Yes, to write the map | Pointer-table and decompression discovery from the code that reads them (A13) |
| Level data | `scripts/model/smb-levels.py`, written once by a lane, deterministic after | Once per game | The same, from the area parser's reads (A13) |

| The clip corpus | `gp capture corpus`: cells by mechanic, pattern and context, perturbation identifiability | No | Already deterministic; add clips aimed at each open hypothesis (A14) |

The stages that still need an LLM all reduce to two questions: what does this byte mean, and what rule writes it. Both have a deterministic answer when the code is available, since the code is the rule.

## 2. Algorithms

Each entry says what it is, what it would do here, and where it comes from. Sources are listed at the end.

### A1. Trace-based RAM role inference

For each RAM byte over a recording: how often it is written per frame, whether it is read by the code that also reads the controller, its correlation with each input bit, with each sprite's OAM x and y, and with the frame counter. A byte whose change follows another byte's value is a speed of a position; a byte that steps by 1 every frame and wraps at 256 is a clock; a byte that counts down and is reloaded is a timer; a byte that is 0 or 1 and gates other writes is a flag. Mappy (Osborn, Summerville and Mateas, FDG 2017) finds NES objects and scrolling from an instrumented emulator with no game-specific code. Tom Murphy VII's learnfun (SIGBOVIK 2013) finds RAM bytes that rise over play of Super Mario Bros. by lexicographic orderings. Emulator RAM search (FCEUX's RAM Search, Mesen's access counters for reads, writes and executions per address) is the manual form of the same thing. Daikon (Ernst et al., IEEE TSE 2001) finds invariants over traced variables, among them `x = a (mod b)`; DIG (Nguyen, Kapur, Weimer and Forrest, ICSE 2012) finds polynomial relations, so `x' = x + vx` comes out as an equation. Game Printer has the start of this in `gp track` and the position-by-speed measurement check.

### A2. Dynamic slicing of the writer

Given a measure that parts at frame F, find the instructions that wrote its byte on frame F and the bytes they read, back to the inputs of that frame (a backward dynamic slice). The slice is the routine that owns the measure and the bytes it depends on. Weiser (ICSE 1981) defines program slicing; Korel and Laski (Information Processing Letters, 1988) define the dynamic form over one run. `gp trace instructions` already prints every instruction in a window; a slice needs the write addresses per instruction, which the event log hook could add. The slice turns "No mechanic owns it" into a routine name, which is today the step lanes do by reading the disassembly.

### A3. Symbolic execution of the writer

Run the sliced routine with its input bytes symbolic and get the update rule as an expression: `vy' = if vy >= 4 and frac >= 0x80 then 4 else vy + g`. angr (Shoshitaishvili et al., IEEE S&P 2016) has a P-Code engine, and pypcode, angr's binding to Ghidra's SLEIGH, ships a 6502 language (`6502:LE:16:default`). Ghidra's own 6502 processor module gives P-Code for the decompiler. The expressions go to Z3 (de Moura and Bjorner, TACAS 2008) to compare with the model's rule: equal, or a counterexample frame. This is the step from "every number is the code's" to "here is the shape the code has".

### A4. Synthesis over a DSL of mechanic parts

The mechanic options are a small language already: bands, caps, `every`, `phase`, gates on a flag, holds, wraps. Enumerate compositions of options in size order and keep the first that reproduces the original's series on every clip that holds the measure. FlashFill (Gulwani, POPL 2011) and FlashMeta/PROSE (Polozov and Gulwani, OOPSLA 2015) synthesize programs in a DSL from examples by version-space search; AutumnSynth (Das, Tenenbaum, Solar-Lezama and Tavares, POPL 2023) synthesizes reactive game programs from observed grid worlds and adds latent automaton state when a pure function can't fit, which is the case of timers and modes here. CHARDA (Summerville, Osborn and Mateas, IJCAI 2017) learns a hybrid automaton of a game character's modes and the guards between them from traces, and Summerville, Osborn, Holmgard and Zhang (FDG 2017) measured jump parameters across NES platformers in an instrumented emulator. Guzdial, Li and Riedl (IJCAI 2017) learn a Super Mario Bros. engine from video by greedy search over rules. A4's search space is the model's own options, so its answers are model text with no new code.

### A5. Counterexample-guided search

When A4 or a numeric fit has candidates, check each on every clip and add the first clip that fails as a new constraint, instead of scoring everything every time. CEGIS is from Solar-Lezama et al.'s sketching (ASPLOS 2006). The refine loop's whole-run check is a slow form of it.

### A6. Change points and phases

Split a series into stretches where one rule holds: constant, linear, a fixed step, a cap. PELT (Killick, Fearnhead and Eckley, JASA 2012) finds the optimal split under a penalty in linear time; the `ruptures` package (Truong, Oudre and Vayatis, Signal Processing 2020) implements it and the other offline methods. Adams and MacKay's Bayesian online change point detection (2007) does it frame by frame. The splits are the phases of a part freeze, a shrink's four states, a timer's reload. `gp_extract::feel::free_flight` already cuts jump arcs by hand-written rules; a change-point pass would cut every measure the same way.

### A7. Finite differences and pattern classes

Take first and second differences of the original's series in the window and classify: constant, linear (constant first difference), quadratic (constant second difference: gravity), piecewise of those, periodic with period N, mod-N (wraps), gated by a flag (the difference is one value when a byte is set and another when not). Periods come from autocorrelation; the shortest linear recurrence over the bytes comes from Berlekamp-Massey (Massey, IEEE Trans. Information Theory, 1969). The loop study's detector 3 ("one number gives the same change every frame") is the first class of this; the rest would name the shape in the question instead of only saying it doesn't fit.

### A8. Exact arithmetic recovery

The NES works in bytes, so every diff is a sum of a few fractions of a power of two. Write the diff as a rational in lowest terms: 1/64 is a fraction byte step, 1/2 is a half-pixel from a 16ths speed, 4 is an anchor offset, 256 a wrapped low byte. Rational reconstruction by continued fractions (Python's `Fraction.limit_denominator` is the standard implementation) gives the denominator. A constant whole diff from the first frame is an anchor or spawn offset; a diff that is the fraction of one byte means a fraction not carried or a carry taken a frame apart. No search is needed: the diff names the byte.

### A9. Delta debugging for the first wrong frame and its cause

The first wrong frame is found already. Delta debugging (Zeller and Hildebrandt, IEEE TSE 2002) then isolates the cause: copy the original's state into the model's for subsets of fields at frame F-1 and step once; the smallest set of fields that makes frame F exact is the missing state or the wrong rule. It is a bisection over state, as `git bisect` is over commits. The translation from the original (`translate::from_original`) already does the copying.

### A10. Frame-counter modulo detection

For a rule that fires on some frames only, tabulate the frames it fires on against FrameCounter mod 2, 4, 8 and so on, and against the other clocks A1 finds. A rule that fires only on one residue is `every = N, phase = r`. Daikon's modulus invariants are the same test. This would have found `contact.every = 2` and the hammer's `phase = 1` from the touch frames alone, and `path.every` for the piranha plant.

### A11. Contact and collision-box inference from hit frames

Each frame where a touch or a landing happens, and each frame where it nearly did and didn't, gives a linear inequality on the box offsets (the relative x and y of the two bodies). Intersect them: the result is the box, or proof that no box fits, which means the test is on points (a head point, foot points) or on some frames only (A10). For tile collision, the same with the tile under each probe point and its kind gives the probe points and which metatile kinds are solid. This is interval arithmetic, or a small linear program; Z3 handles the case with frame parity in it.

### A12. Presentation routing

A diff on the screen measure with every simulation measure exact is presentation. A1 on PPU writes (palette and OAM) finds the byte that drives it, as ColorRotateOffset drives the ? blocks' colors. Such a byte is mapped as a presentation field and never fitted.

### A13. Asset and level reads from the code

Find tables by the code that indexes them: a load with an index register from a label is a table, a pair of loads into a zero-page pointer is a pointer table, a loop that reads a stream and branches on its high bits is a decompressor or an object parser. The data deriver already reads tables a label names through the asset map; the step is writing the map's entries from the traced reads instead of by hand. Mappy's room and tile output covers levels seen in play.

### A14. Clips aimed at a hypothesis

When two hypotheses (two DSL programs, two boxes) agree on every clip, make the clip where they differ: a start and presses that reach the frame where the two disagree. The clip corpus report (docs/research/clip-corpus.md, section 5) already asks for two independent clips per number; this extends it to shapes.
