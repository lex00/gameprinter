# Finding play no run has made yet

`gp localize GAME` looks for behaviour none of a game's runs has reached and sends a search to it. It came from game-printer on 2026-11-13, where it was built to find Super Mario Bros.' hidden 1-up block with the tools told nothing about it (game-printer's research report on easter eggs as a probe test).

| Step | What it does |
|---|---|
| 1. One-way branches | Every clip of the game's mechanic sessions (except harvest and jumpathon ones) and every blind farm run of its ROM is replayed while each conditional branch is watched. A branch that ran in the level but only ever went one way is a lead |
| 2. Guards | The frame each lead first ran is replayed with the writer slicer (`gp_nes::slice`), and the instruction that set the branch's flag is sliced back to the RAM bytes and constants it came from. When the flag came from comparing one RAM byte with a constant, the values that would send the branch the other way are worked out |
| 3. Places | A guard that read the level grid (the mapping's `[cells]`) is checked against the grid as the runs saw it: a cell that holds a value the other way needs is a place, and where the cell sat from the player each time the guard ran says how to meet it |
| 4. Probes | Go-Explore from a savestate before the place, with the moves ordered by the decision model (`--decide`), at random, or not aimed, scored by the distance to meeting the cell as the guard does; it stops when the branch goes the other way. `--no-probe` stops before this step |

The game is its package in the games checkout: the level key is its `observe.toml` `[level]` (`--level`, Donkey Kong's `main` by default), the grid its `mapping.toml` `[cells]`, the player's bytes the ROM dataset's or the mapping's `entities.player[0].x` and `.y`. With `--rom` and no game, blind discovery finds the player and the whole run is one level. `--poke` adds a sweep that puts the player beside each grid cell along the furthest run; `--collect`, `--check-log` and `--grade` are the grader's parts (a run checked for the branch going the other way, against a store recording).

The leads are written to `$GP_HOME/work/localize/GAME/LEVEL.json` and a probe's or a collect's winning run to `$GP_HOME/work/localize/runs/`. `--out DIR` writes both into DIR instead (`DIR/LEVEL.json`, `DIR/runs/`), so a trial run leaves the home's leads as they were. A ROM nothing has played still gets its first blind run in `$GP_HOME/work/farm/blind/`, which later runs read as one of their sources.

On an NES game it reads the 6502. On an arcade romset it runs steps 1 and 2 over the main Z80 (`crates/gp-cli/src/localize_z80.rs`): each conditional jump, call and return (`jr cc`, `jp cc`, `call cc`, `ret cc`, `djnz`) is counted the way it went from gp-arcade's instruction trace, as `crates/gp-cli/src/covered.rs` counts it, and the guard is the latest instruction before the jump that set the flag its condition reads (Z, C, S or P/V; B for `djnz`), in the same interrupt context, walked back with the walk `gp element inputs` uses from a write (`crate::element_z80::walk_back`) to the RAM bytes it came from. The values that send it the other way are worked out for the eight-bit arithmetic and logic, `inc`, `dec`, `bit` and the rotates' carry. A session's clips count only when its `session.toml` names the same romset. An observe.toml with no `[level]` (Tapper's) counts every frame, as level `all`, and says so.

Step 3 runs on arcade for a model in the board's own units, whose state mapping says `board_units = true` (feature `platform.board_units`, docs/formats/state-mapping.md, "An arcade original"): a place meets a grid cell from the player, so the grid and the player's place must be in one unit, and only that marker promises it. A cell is then the model's `tile_size` (8 on MCR) of the player's units, from the level named by `--level` or else the model's first; the grid is the mapping's `[cells]`, read through the board's addresses (E000 on), and the player's place the mapping's `entities.player[0].x` and `.y` with their `scale` and `offset`. The board doesn't scroll, so a page's columns follow the one before's. Each guard on a grid byte gets the cells that held a value sending it the other way and where its cell sat from the player (`meets`), and the leads with cells are ranked as on the NES. Without the marker, without `[cells]` or without the player's fields, the step says why in one sentence (`places`), and steps 1 and 2 run as before; Tapper's mapping has neither the marker nor `[cells]` today. Step 4 and `--poke`, `--collect`, `--check-log` and `--grade` are refused on arcade: the probes play from the NES emulator's save states, and gp-arcade's aren't wired to them.

On Tapper (9 clips of the tapper romset's sessions, 13212 frames, 2 minutes in a debug build): 479 conditionals, 179 one way, every guard read. The lead with the most unrun code behind it is the jump at $27BF, guarded by `or a` on a byte read through a pointer from E28F; the third, at $26AE, is `cp $06` on E4A8 (the levels cleared, 2 on the frame it first ran): 250 values send it the other way, 6 and up, which no clip reaches.
